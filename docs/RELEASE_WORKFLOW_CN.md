# 发布流程（建议执行顺序）

## 初次投稿前

1. 保留本目录为匿名审稿包，不写作者姓名、医院名称、邮箱或Git提交者信息。
2. 运行合成示例和隐私扫描，确认没有本地绝对路径、患者编号、结局表、个体预测、CT或标签文件。
3. 将目录压缩为 `rectal-ct-rfs_review-v1.1.0_latest-clinical.zip`，作为 Supplemental Software for Review 上传ScholarOne。
4. 在匿名主文中采用 `MANUSCRIPT_AVAILABILITY_TEXT.md` 的“匿名初投稿版本”。
5. 在完整标题页加入规定的数据共享声明；完整标题页不发送给审稿人。

## 接收前或接收后按编辑部要求

1. 新建公开GitHub仓库，例如 `rectal-ct-rfs`。
2. 删除匿名占位符，在 `CITATION.cff`、许可证和README中填入作者及正式引文信息。
3. 提交并记录完整40位commit SHA。
4. 创建GitHub Release `v1.1.0`，不要再修改该标签对应内容。
5. 将GitHub仓库连接Zenodo，归档 `v1.1.0` 并获得DOI。
6. 把GitHub URL、commit SHA和Zenodo DOI替换进主文代码可用性声明。
7. 至少维护公开仓库和归档链接5年。

## 不得上传

- 原始或去标识化CT图像；
- 原始分割标签或可重建标签；
- 临床Excel/CSV、患者编号映射表、随访时间和结局；
- 患者级衍生特征、风险评分或预测文件；
- 含本机路径、用户名、医院内网地址、访问令牌或密码的配置；
- 原始 `M12_latest_clinical.joblib`（其中保留了开发队列的患者级随访和结局字段）。

## 可公开

- 经隐私清理的分析、训练与推理代码；
- 冻结的预处理参数和不含个体数据的模型参数；
- 自监督3D CNN编码器权重；
- 特征名称、变量字典、合成示例和汇总性能；
- 软件环境、版本、许可证和模型卡。
